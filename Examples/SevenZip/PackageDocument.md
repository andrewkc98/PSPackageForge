### Detection contract

Both ConfigMgr and Intune run the same generated detection script, but they disagree on what
a non-zero exit code means:

- A non-zero exit means the detection **mechanism itself failed** -- it could not complete its
  check, not that the application is absent.
- **ConfigMgr** treats a non-zero exit as Unknown and does not take action based on it.
- **Intune evaluates a non-zero exit as "not installed"**, which can trigger a reinstall
  attempt even though the application may already be present. Review detection failures on
  Intune-targeted deployments especially carefully.

## Never query Win32_Product

Querying `Win32_Product` (via `Get-CimInstance`, `Get-WmiObject`, or any other means) forces
Windows Installer to reconfigure every MSI-installed application on the machine.
This is the single most common packaging mistake -- do not add it to any discovery, detection,
or troubleshooting step for this package.
